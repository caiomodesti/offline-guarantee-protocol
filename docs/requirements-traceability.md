# Critical requirements traceability

| Requirement | Design decision | Trust assumption | Threat | Mitigation | Future test |
|---|---|---|---|---|---|
| Bounded offline branch | Signed remaining state and `branch_spending_limit` | Correct SDK arithmetic | Honest/malicious overspend | Checked transition and reachable-path validation | Multiple payments; exact-limit; limit+1; overflow fuzz |
| Prove parent reachability | Complete genesis-to-tip proof bundle, depth <= 32 | Merchant retains/relays canonical bundle | Device invents independent parent roots to evade forks | Verify every transition from signed genesis; permissionless relay to fixed destinations | Missing/reordered/fabricated ancestor; maximum depth; branch rollback |
| Bounded protocol liability | `collateral_coverage_cap` locked on-chain | Program/SPL correctness | Fork aggregate exceeds collateral | Settlement invariant and full-cap reserve | Double/triple branch above cap; conservation property |
| Distinguish exposure concepts | Branch limit, aggregate metric, coverage cap are separate fields | Integrators display correct semantics | Misleading guarantee | Normative definitions and UI copy contract | Schema/API snapshot and UX assertion tests |
| Portable offline verification | Issuer-signed certificate plus wallet device authorization | Issuer accurately reads finalized state | Fake/stale certificate | Issuer signature, immutable on-chain match at claim | Fake issuer; changed field; inconsistent chain account |
| Certificate matches program state | Issuer signs finalized `ACTIVE` session; program cross-checks immutable fields at claim | Issuer accuracy and key safety | Off-chain certificate diverges from active state | Mismatch is rejected; issuer has no activation/custody authority | Wrong-hash/field certificate; issuer signer mismatch |
| Scoped device compromise | Per-session device key, time, branch and cap bindings | Wallet authorization key safe | Wallet key reused/exposed | Separate signature domains and one-session key | Wrong device/session/domain key tests |
| Merchant binding | Merchant authority and random challenge signed | Merchant CSPRNG/key safe | Credential theft/redeem by B | Claim signer/destination must equal signed merchant | Merchant mismatch and challenge mutation |
| Deterministic bytes | Canonical Borsh with frozen v1 schemas | Library implementations conform | Cross-client ambiguity/malleability | Cross-language vectors and strict decoder | Rust/TS golden hex; trailing bytes; reordered fields |
| Cross-domain replay prevention | Genesis hash, environment, program, versions, object, session in domain | Client configured to right domain | Localnet/devnet/program replay | Exact domain comparison on every verify | Mutation matrix for every domain field |
| Replay-safe claims | Claim PDA keyed by credential hash plus unique economic state-edge record | Hash collision infeasible | Exact or metadata-only wrapper replay settles twice | `DUPLICATE_CREDENTIAL` / `DUPLICATE_STATE_EDGE`; one counter/allocation per edge | Exact duplicate, distinct wrapper/same edge, duplicate before/after settlement |
| Formal fork detection | Valid reachable sibling child-set cardinality >1 | Signature/hash primitives sound | Rollback/double spend | Program-verifiable two-edge witness | Normal/simple/triple/invalid/replay graphs |
| Invalid evidence cannot revoke | Invalid edges excluded before graph | On-chain verifier parser correct | Framing payer with garbage | Signature, transition, domain, reachability checks | Bad sig/parent/merchant/sequence fork witnesses |
| Arrival-independent coverage | Freeze after deadline, pro-rata, hash dust ordering | All timely claim accounts included | Front-running/withholding changes payout | On-chain count/sum and sorted paginated inclusion | All claim permutations yield identical allocations |
| Both branches can claim | Every valid unique edge eligible | Merchant presents evidence by deadline | Hidden competing claims | Shared cap disclosed; `FULLY_COVERED` or `INSOLVENT` pro-rata | Two merchants full/insolvent cases |
| Claim timing | Expiry distinct from 6h claim deadline | Merchant local clock is approximate | Late generation/submission | Local expiry check and authoritative submission deadline | 12:00/15:00/21:00 boundaries; late submit; backdated risk |
| Two-phase claims | Collect `SUBMITTED`, freeze/finalize after deadline, then settle | Permissionless finalizer eventually runs | First-arrival payout manipulation | Program forbids settlement during claim window | Attempt early settlement; claim permutations; interrupted finalization |
| Safe withdrawal | Reserve full cap until resolution, then unpaid allocations | Accurate SPL balance/account constraints | Drain before merchant reconnects | Atomic reserve formula and PDA custody | Withdrawal at every lifecycle state and concurrent claims |
| Conflict revocation | Fork record and profile revocation atomic | Program transaction atomicity | Continued session creation after fraud | Same instruction updates both and checks profile on creation | Forced failure/new session after accepted witness |
| Claims survive revocation | Revocation does not erase claim eligibility/reserve | Settlement path remains callable | Payer causes revocation to escape debts | Separate profile/session/claim state machines | Settle eligible claims after revocation |
| No implicit reconciler trust | Hybrid verifiable architecture | Solana program executes specified checks | Malicious omission/allocation | Count/sum, claim inclusion, witness/allocation verification | Omit/duplicate/reorder batches; resume permissionlessly |
| Economic source of truth | PDA vault/accounts/events | Solana/SPL security | DB/UI fabricates settlement | Frontend derives confirmed chain facts | Delete index; rebuild; compare token deltas |
| Provisional attack headline | Production verifier yields authenticated incompatible credentials | Reconciler runs unmodified verifier | Fake local banner | Label provisional; attach credential hashes/predicate output; no economic effect | Invalid/mutated pair cannot produce provisional result |
| Authoritative demo headlines | Evidence-to-event-to-state contract | RPC/indexer eventually returns confirmed data | Fake confirmed banners | `AuthenticatedForkConfirmed`, coverage/application, revocation events plus account checks | Delete/replay index; mutated evidence produces no chain headline |
| Trivial self-merchant | Payer and merchant wallets must differ | Address ownership is not identity | Payer pays itself | Reject equal addresses; disclose multi-wallet bypass | Same-address reject; two-wallet scenario remains open risk |
| Session-scoped collateral | Reserve only `collateral_locked` from a larger vault | Vault accounting is correct | Over-lock or withdraw reserved funds | Reserve sum and actual SPL balance checked atomically | Vault 1000/lock 500/withdraw 500; reject 501 |
| No PII | Opaque attestation hash/reference only | Issuer keeps PII off-chain | Identity disclosure | Account schema rejects PII fields | IDL/schema review and fixture scan |
| KYC does not decide historical claims | Attestation gates profile/session creation only | Configured issuer is honest for assurance status | Later KYC expiry/revocation harms merchants | Existing timely credentials remain eligible; future sessions blocked | Expire/revoke attestation after payment, then settle claim and reject new session |
| Privacy honesty | Document correlation leakage | Public chain observable | User deanonymization | No privacy claim; per-session device keys | Metadata mapping review; key-reuse detection |
| Checked financial math | `u64` state, `u128` intermediates | Correct implementation | Overflow/underflow/dust extraction | Checked operations and deterministic rounding | Max-u64 property/fuzz tests |
| Pause safety | Separate emergency authority; liabilities preserved | Emergency key controlled | Admin steals/unlocks under pause | Pause cannot withdraw reserves or erase claims | Pause during active/conflicted/settling states |
| Offline QR integrity | Fragmented `OGPQR1` frames commit to complete canonical payload hash | SHA-256 collision resistance and correct camera bytes | Missing, mixed, reordered, duplicate, or tampered frames | Out-of-order assembly, identical-duplicate idempotency, strict count/kind/size/hash checks | Two-device scan with dropped/mixed/tampered frame corpus |
| Offline merchant acceptance | Complete portable chain plus exact outstanding challenge is verified before UI acceptance | Configured issuer key and merchant device state are authentic | Local dashboard fabricates `Guarantee present` | Shared verifier checks domain, issuer, authorization, reachability, signature, merchant, amount, and challenge | Wrong issuer/program/merchant/amount/challenge tests; physical airplane-mode run |
| Payer restart safety | Persist new proof bundle before displaying credential | Local storage durability and SecureStore availability | Restart rolls payer back to genesis and creates accidental fork | Rehydrate verified final tip; resume unacknowledged delivery; storage failure blocks payment | Kill/restart before display, during scan, and before receipt on physical device |
| Merchant evidence durability | Persist proof frames before acceptance and restore outstanding challenge | Device storage remains available | Crash loses claim or reuses challenge | Async persistence precedes acceptance; hash-idempotent pending claims | Kill/restart at every QR phase; verify claim survives offline |
| Merchant claim reconnect | Durable proof remains pending until a matching confirmed claim account is observed | RPC/relayer eventually becomes available before the deadline | Lost response causes duplicate retry or local signature is mistaken for settlement | Hash lookup before/after submit, exact proof materialization, confirmed field/slot match, isolated retry errors | Inject timeouts, ambiguous success, mismatch, multi-claim failure; physical reconnect with real RPC adapter |
| Mobile key separation | Per-session/device secrets in native secure storage; public evidence in AsyncStorage | OS Keychain/Keystore is not compromised | Unencrypted storage leaks signing key | Never place payer device secret in AsyncStorage; wallet private keys are never held by Sprint 7 apps | Storage inspection, backup/restore, rooted-device threat test |
| Payer data-loss recovery | Local loss cannot erase the authoritative session or mint fresh offline capacity | Solana account reads and wallet signatures are authentic | Clear data/reinstall resets balance and duplicates exposure | Fail closed; require online confirmed `active_session` read plus wallet authorization; block reprovisioning while prior session is active | Unit decision matrix; Android clear-data/reinstall test; validator E2E with retained merchant claim |
| Payer signed-session restoration | Offline reboot may resume only the exact confirmed and cryptographically bound branch | Configured issuer/domain roots and protected storage are authentic | Partial backup, edited balance, substituted wallet/profile/session, or forged “confirmed” metadata enables fresh spending | Revalidate 370-byte authorization, 554-byte certificate, protected device key, full QR chain, stored final state, account owner/address, and non-stale confirmed contexts | Host tamper matrix plus validator-backed controller recovery; physical kill/restart and partial-backup tests |
| Confirmed offline provisioning | Session transaction and facts are confirmed before any offline authorization/certificate is issued | RPC honestly reports the requested commitment | Processed transaction is dropped or temporarily unobservable after the device gains offline authority | Confirm transaction and refetch program-owned session at `confirmed`; bind all portable material to those facts | Physical RPC interruption/reorg simulation; reject provisioning from processed-only state |
| Ordered portable authorization | Wallet signs finalized session facts and issuer signs only after the authorization hash is registered | MWA returns signatures for the authorized wallet; issuer independently reads Solana | Client fabricates timestamps/limits or issuer certifies an unregistered session | Deterministic create → confirm/refetch → wallet message signature → register → confirm/refetch → issuer → validate → persist sequence | Concrete MWA adapter test; issuer endpoint replay/substitution test; interrupted-step recovery test |
| Normal portable E2E | The exact credential verified from QR becomes the on-chain claim and payout | Configured issuer and injected wallet signer represent their declared authorities | App reconstructs different claim bytes or payer absence blocks merchant settlement | SDK derives payload/signature/hash directly from verified credential; runtime relayer submits; PDA settles and permissionless close completes without payer signer | Runtime gate PASS in run 31901840994; repeat through production mobile controllers on two physical phones |
