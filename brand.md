## Gradients

Two restrained gradients are allowed. Never place small body text directly on the accent gradient.

```css

--gradient-bg-light: linear-gradient(135deg, oklch(0.98 0.012 245) 0%, oklch(0.95 0.017 260) 100%);
--gradient-accent-dark: linear-gradient(to right, oklch(0.77 0.19 245) 0%, oklch(0.78 0.17 275) 100%);
--gradient-accent-light: linear-gradient(to right, oklch(0.44 0.19 245) 0%, oklch(0.46 0.17 275) 100%);
```

Use the subtle gradient for hero backgrounds and the accent gradient for thin bars, diagram paths, and premium labels. Use at most one gradient per visual surface.

## Tone and voice

### Use

Write directly and specifically. Lead with verifiable outcomes, numbers, state transitions, and trust assumptions. Prefer “liability is capped at the locked collateral” over “safer payments.” Use short sentences and explicit limitations.

### Avoid

Avoid hype, urgency, emojis, exclamation marks, and claims such as “eliminates double spending,” “trustless offline payments,” “production ready,” or “guaranteed payment” without the exact coverage condition. Do not use “revolutionary,” “seamless,” “game-changing,” or “unlock.”

### Voice example

> A compromised offline device can create conflicting branches. OGP detects valid forks, caps protocol liability at locked collateral, settles eligible claims deterministically, and revokes offline access atomically.

## Visual language

**Do:**

- use dark protocol surfaces, cobalt evidence paths, restrained violet highlights, and near-white copy;
- render state names and economic values in mono with tabular numerals;
- distinguish `PASS`, `OPEN GATE`, `OPEN RISK`, and `DEFERRED` visibly;
- show limitations beside guarantees;
- use diagrams for custody, evidence flow, reconciliation, and roadmap state.

**Do not:**

- use neon rainbow crypto gradients;
- use coins, rockets, shields, padlocks, or generic AI imagery as primary symbols;
- imply chronological order from offline timestamps;
- hide trust assumptions in footnotes;
- place more than one accent gradient on the same surface.

## Repository presentation

- Hero: one-line category, primary claim, exact current sprint status.
- Badges: build/runtime/mobile status and explicit experimental-state badge.
- Diagrams: system architecture, offline-to-online lifecycle, deterministic reconciliation, and immutable roadmap.
- Navigation: product, protocol, security, ADRs, sprint evidence, run locally.
- Every status statement must link to evidence in the repository or a pinned CI run.
